# CONTEXTUAL_UI_STANDARD.md

Статус: активне джерело правди.

Контекстний UI дозволений, коли він справді залежить від поточного вибору або режиму.

## Дозволені патерни

- inline mini-toolbar;
- context menu;
- inspector;
- sticky strip;
- popover з параметрами.

## Правила

- Не дублювати весь toolbar.
- Не приховувати критичні для молодших учнів параметри в нестабільний floating UI.
- Не зсувати workspace без потреби.
- Не створювати кілька різних способів виконати одну дію, якщо це не прискорює реальний сценарій.
- Якщо дія стандартна (`new/open/save/undo/redo`), вона має йти через command adapter, а не через контекстний виняток.

## Контекстне меню

- У робочій області редактора правий клік відкриває наше меню, а не меню браузера. Реалізація — лише через `OfficeUI.bindContextMenu` (див. `UI_INTEGRATION_GUIDE.md`).
- Меню показує дії для того, на чому клікнули: виділення, об'єкта, клітинки або порожнього місця. Порожні групи не показуються.
- Пункти викликають ті самі дії, що й головне меню; нових дій, доступних лише з контекстного меню, не додавати.
- Shift + правий клік і сенсорне довге натискання лишають меню браузера. Поле, де учень зараз редагує текст, теж може лишити меню браузера.
- У Малюнках права кнопка на полотні малює другим кольором, тому там контекстного меню немає.
- Покриття: Текст (документ, таблиця), Таблиці (клітинки, заголовки рядків і колонок), Слайди (об'єкт, порожня ділянка слайда, мініатюри), Вектор (об'єкт, полотно), Схеми (блок, стрілка, полотно).

## Перевірка

Контекстний UI переважно перевіряється ручним QA. Статичний аудит ловить лише базові контракти shell, команд, modal/dropdown і стилів.
