# UI_MIGRATION_TO_STANDARD.md — ПЛЮС Слайди

## Поточний Стан

Базовий shell, command adapter, file picker і runtime-аудіт підключені. `slides/js/runtime.js` лишається стабільним module entrypoint, а `slides/js/app.js` тепер є координатором верхнього рівня, не єдиним місцем усієї логіки редактора.

Поточний прохід зменшив технічний борг без надмірного збільшення кількості файлів: з `app.js` винесено тільки ті частини, які мають самостійну відповідальність і потрібні для майбутнього PowerPoint-подібного функціоналу.

## Поточна Структура

- `slides/js/runtime.js` — module entrypoint, який стійко запускає `SlidesApp.boot`.
- `slides/js/app.js` — boot, UI coordinator, command dispatch і зв'язування модулів.
- `slides/js/chart-controller.js` — insert/edit modal orchestration діаграм через явні callbacks `app.js`.
- `slides/js/chart-element.js` — модель, нормалізація, parser табличних даних і спільний SVG-рендер діаграм.
- `slides/js/project.js` — нормалізація презентації/елементів, import/export JSON payload, filename slug.
- `slides/js/element-rendering.js` — спільні visual text styles і SVG-геометрія фігур для stage/export.
- `slides/js/image-geometry.js` — спільна чиста crop-геометрія для stage та export.
- `slides/js/object-commands.js` — чисті правила group/ungroup/remap, selection units, align і distribute.
- `slides/js/presentation-design.js` — чисті доменні операції тем і макетів без DOM, history та runtime state.
- `slides/js/slide-list.js` — thumbnails, drag reorder і кнопки керування слайдами.
- `slides/js/stage-renderer.js` — DOM-рендеринг сцени, елементів, resize/rotate handles і selected-state.
- `slides/js/table-controller.js` — selection, clipboard, структурні команди та modal orchestration таблиць через явні callbacks `app.js`.
- `slides/js/table-element.js` — модель, нормалізація, доменні операції та спільний stage/export DOM-рендер таблиць.
- `slides/js/text-list.js` — створення, рендеринг і читання маркованих/нумерованих текстових блоків.
- `slides/js/stage-interactions.js` — pointer state, drag/resize/rotate, рамка вибору (marquee), smart guides + прив'язка (екранний поріг, AABB з урахуванням rotation), rotation-aware resize.
- `slides/js/modal-ui.js` — show/close/info/confirm modal behavior.
- `slides/js/state.js` — локальний state і serialization.
- `slides/js/history.js` — undo/redo stack.
- `slides/js/storage.js` — autosave draft у IndexedDB з graceful-фолбеком на localStorage і міграцією старої localStorage-чернетки.
- `slides/js/templates.js` — створення слайдів, елементів і макетів.
- `slides/js/export.js` — PDF export, print і snapshot rendering.
- `slides/js/utils.js` — DOM, file і utility helpers.

## Реалізовано (хвилі 0–4.2)

- **Хвиля 0 — надійність ядра:** коректний undo/redo (commit-after, коаліс­ція drag/typing), розділені статуси `dirty`/draft-saved/file-saved, захищена versioned-нормалізація імпорту (ліміти, allowlist кольорів, нейтралізація зовнішніх URL, унікальні ID), автозбереження в IndexedDB з фолбеком на localStorage і реконсиляцією за часом.
- **Хвиля 1 (частково) — мультивибір:** `selectedElementIds`, shift-клік, Ctrl+A, marquee, груповий drag/нудж/delete/copy/paste, форматування за всіма вибраними. (№6 align/distribute/group — ВІДКЛАДЕНО.)
- **Хвиля 2 — зручне полотно:** zoom (фіксована сцена 960×540 + transform-scale, fit-to-window, Ctrl+±/0, Ctrl+колесо); smart guides + прив'язка до країв/центра/об'єктів + сітка; rotation handle, Shift-пропорції resize, rotation-aware resize, Alt+drag-дублювання, контекстне меню (миша + Shift+F10); доступність (alt text зображень, видимий focus, Tab-цикл об'єктів, ↑/↓ між слайдами, aria-labels).
- **Хвиля 3.1 — базове форматування текстового блока:** локальні сімейства шрифтів, довільний розмір 4–400, довільний міжрядковий інтервал 0.8–3 (зберігається при відкритті/відновленні), нормальна/жирна вага 400/700; однаковий рендер на полотні, у мініатюрах і PDF/print; allowlist-нормалізація нових полів та версія текстової моделі у файлі.
- **Хвиля 3.2 — списки текстового блока:** марковані й нумеровані списки з перемиканням у toolbar, семантичним `ul`/`ol`-рендером на полотні, у мініатюрах і PDF/print, Undo/Redo та allowlist-нормалізацією `listType`.
- **Хвиля 3.3 — заміна зображення:** заміна вибраного зображення з файла або URL зі збереженням його `id`, позиції, розміру, повороту, шару й вибору; alt можна зберегти або змінити; операція підтримує Undo/Redo. HTTPS-посилання вбудовуються в `data:` одразу при вставці/заміні (fetch+encode), тож у моделі зберігається лише `data:` — зображення переживає перезбереження й працює офлайн, а сирі зовнішні URL не потрапляють у файл; невалідне джерело лишає модалку відкритою з інлайн-поясненням.
- **Хвиля 3.4 — оформлення зображення:** режим вписування в рамку (`cover`=заповнити з обрізанням / `contain`=вписати повністю) і прозорість 0–100% («прозорість», 0%=видиме); неруйнівне **кадрування** (crop) — частки рамки `l/t/r/b`, режим із crop-ручками й затемненим «привидом» обрізаного, вихід Esc/Enter, Undo/Redo; окрема група тулбара з'являється лише коли вибрано зображення; однаковий рендер (через вікно `overflow:hidden`, без `clip-path`) на полотні, у мініатюрах і PDF/print; allowlist-нормалізація `objectFit`, clamp `opacity` та `crop`.
- **Хвиля 3.5 — базові лінії та стрілки:** вставка з меню й тулбара, allowlist-нормалізація, однаковий SVG-рендер на полотні, у мініатюрах і PDF/print; вибір, drag, зміна довжини зліва/справа, rotation, шари, копіювання та Undo/Redo працюють через спільну модель `shape`.
- **Хвиля 3.6 — текст у фігурі:** прямокутник, коло й трикутник зберігають напис у власному `shape.content`; один клік/drag працює з фігурою, подвійний клік входить у редагування; доступні звичайне текстове форматування, списки, Undo/Redo та однаковий рендер на полотні, у мініатюрах і PDF/print. Службові placeholder-и видно в редакторі та мініатюрах, але вони не потрапляють у показ, PDF чи друк. Лінії та стрілки текст не підтримують; файловий контракт позначено `textModelVersion: 3`, щоб старі версії не втрачали нові написи мовчки.

- **Хвиля 4.1 — теми оформлення (дизайн-токени):** набір тем (`THEMES`: фон слайдів + узгоджена акцентна палітра, лише локальні кольори для офлайну); picker у меню «Слайд → Тема оформлення…»; застосування оновлює фон УСІХ слайдів і колірну палітру popover, не чіпаючи вміст елементів; `theme` зберігається у файлі/чернетці, нормалізується через allowlist (невідома → `classic`), бере участь в Undo/Redo (serialize/applyPresentationData + renderColorPalette у renderAll).

- **№6 — вирівнювання, розподіл, групування (відкладений пункт Хвилі 1, ЗАКРИТО):** для мультивибору (≥2) — вирівнювання ліворуч/центр-гориз/праворуч/угору/середина-верт/донизу за спільним AABB (з урахуванням rotation); рівномірний розподіл центрів по горизонталі/вертикалі (≥3); **групування/розгрупування** (`element.groupId`, Ctrl+G/Ctrl+Shift+G) із «липким» вибором (клік по члену вибирає всю групу), ремап groupId при дублюванні/вставці (копія — окрема група); окрема група тулбара лише для мультивибору, розподіл активний від 3, «розгрупувати» — лише за наявності згрупованого; усе через Undo/Redo.
- **Хвиля 4.2 — макети слайдів і типізовані placeholder-и:** `LAYOUTS` (blank/title/title-body/two-content/title-image) із типізованими слотами (`title/subtitle/body/image`); picker «Слайд → Макет слайда…» застосовує макет до поточного слайда НЕРУЙНІВНО (реальний вміст лишається, порожні placeholder-и оновлюються, дублікати за типом не плодяться); `slide.layout` та `element.placeholderType` нормалізуються через allowlist і зберігаються; image-placeholder — порожній image-елемент (пунктирна рамка), заповнюється подвійним кліком (через replace-флоу, що знімає `isPlaceholder`); placeholder-и видно в редакторі та мініатюрах, але не в PDF/print/показі; Undo/Redo.
- **Хвиля 5.2 — гіперпосилання:** на об'єкті (текст/фігура/зображення) — посилання `element.link` на https-URL або перехід на слайд; безпечна нормалізація (`normalizeLink`: лише `https://`, блокує `javascript:`/`http:`/`data:`; слайд-посилання з неіснуючою ціллю прибирається при імпорті); модалка «Посилання…» (контекст-меню + меню «Вставка»); у редакторі — бейдж зі скріпкою, активне лише в режимі показу (https → нова вкладка `noopener`, слайд → перехід); серіалізація, Undo/Redo. (PDF растеризований html2canvas, тож кліки лишаються лише в показі.)
- **Хвиля 5.1 — нотатки доповідача:** на кожен слайд — текстові нотатки (`slide.notes`, нормалізація clampText, серіалізація, Undo/Redo з коаліс­цією як у введенні тексту); панель-редактор унизу робочої області (toggle «Перегляд → Нотатки доповідача»); у режимі показу нотатки поточного слайда вмикаються клавішею N (нижня смуга, сховані за замовчуванням); нотатки видно лише в редакторі/показі, не на полотні чи в PDF/print.
- **Хвиля 5.3 — таблиці (ЗАВЕРШЕНО):** окремий елемент `table` (1–20 рядків, 1–10 стовпців) із безпечною нормалізацією комірок і стилю; вставлення через меню/toolbar, редагування тексту безпосередньо в комірках, зміна розміру таблиці зі збереженням наявних даних, структурні команди для активної комірки (рядок вище/нижче, стовпець ліворуч/праворуч, видалення), індивідуальні відносні висоти рядків і ширини стовпців, об’єднання прямокутного діапазону та розділення об’єднаної комірки, перемикач першого рядка-заголовка, готові кольорові стилі та форматування активної комірки або прямокутного Shift+клік діапазону (заливка, колір тексту, жирність, горизонтальне й вертикальне вирівнювання); працюють переміщення/resize/rotation, copy/paste, Undo/Redo, мініатюри, показ, PDF/print і `.artslides` round-trip. Форматування діапазону застосовує лише явно вибрані властивості та може бути очищене до успадкованого стилю; багатоклітинковий діапазон можна очистити Delete/Backspace та копіювати/вставляти Ctrl+C/Ctrl+V разом із форматуванням, тоді як одна активна комірка зберігає нативне редагування тексту. Вставлення й видалення рядків/стовпців автоматично зсуває або змінює merge-діапазони зі збереженням anchor-вмісту; довільна зміна розмірності та clipboard-операції, що перетинають об’єднані комірки, поки вимагають спочатку їх розділити. Руйнівне зменшення або видалення заповненого рядка/стовпця потребує підтвердження; Tab і стрілки переходять між видимими комірками, Shift+стрілка в порожній комірці розширює діапазон, а в текстовій лишається нативним виділенням тексту; DOM має grid-семантику, а імпорт обмежує сумарну кількість табличних комірок. Модель, доменні операції та DOM-рендер таблиці ізольовані в `table-element.js`, а selection/clipboard/modal/command orchestration — у `table-controller.js`; `app.js` підключає контролер через явні callbacks. Подальші drag-ручки розмірів, зовнішній TSV/Excel clipboard та окреме оформлення меж є неблокуючими майбутніми покращеннями.
- **Хвиля 5.4 — базові діаграми (MVP):** окремий елемент `chart` зі стовпчастим, лінійним і круговим типами; заголовок, легенда, до 12 категорій і 4 рядів даних; insert/edit modal із простою таблицею даних, розділеною крапкою з комою; bounded-нормалізація чисел і підписів; спільний безпечний SVG-рендер на сцені, у мініатюрах, показі та PDF/print; переміщення/resize/rotation, copy/paste, Undo/Redo і `.artslides` round-trip працюють через загальну модель елементів. Модель/parser/render ізольовані в `chart-element.js`, modal orchestration — у `chart-controller.js`.

## Хвиля 5 — завершено

Хвилю завершено в межах зафіксованого шкільного MVP: реалізовано нотатки доповідача, безпечні гіперпосилання, таблиці та базові діаграми. Великі домени таблиць і діаграм винесено з `app.js` в окремі модулі моделі/рендерингу та контролери; їх інтеграцію, збереження, історію, показ слайдів, експорт і офлайн-кеш покрито контрактними тестами.

## Хвиля 6 — завершено

- **Хвиля 6.1 — режим доповідача (MVP):** окремий режим показу з поточним слайдом, прев’ю наступного слайда, постійними нотатками, таймером і лічильником слайдів. Запускається через «Перегляд → Режим доповідача» або Shift+F5; клавіша P перемикає звичайний показ і панель доповідача без завершення презентації.
- **Хвиля 6.2 — переходи між слайдами (MVP):** кожен слайд має нормалізований перехід (`none`, `fade`, `slide-left`, `zoom`) і контрольовану швидкість (`fast`, `normal`, `slow`); налаштування поточного або всіх слайдів доступне через меню «Слайд», бере участь в Undo/Redo та `.artslides` round-trip. Ефекти працюють лише в режимі показу, поважають `prefers-reduced-motion` і не впливають на PDF/print.
- **Хвиля 6.3 — контрольований PPTX export:** `pptx-export.js` перетворює слайди на редаговані PPTX-об’єкти: текст, базові фігури, локальні зображення, таблиці з merge/форматуванням, стовпчасті/лінійні/кругові діаграми, нотатки та підтримувані гіперпосилання. Експорт не змінює проєкт і показує користувачу чесний звіт про наближення: переходи, групування, точне кадрування, списки та окремі посилання не гарантують повного збігу.

Залежність для Хвилі 6.3 — vendored browser bundle **PptxGenJS 4.0.1** (`vendor/pptxgenjs/pptxgen.bundle.js`, 460889 байтів) з MIT-ліцензією у `vendor/pptxgenjs/LICENSE`. Вона прибирає ризик ручного складання OOXML/ZIP, працює повністю офлайн, не додає build/server runtime і lazy-load-иться лише під час першого PPTX export. Exit plan: видалення adapter-а і vendor-каталогу не впливає на `.artslides`, PDF, показ або модель редактора.

## Хвиля 4.5 — стабілізація (ЗАВЕРШЕНО)

Хвилю завершено після стабілізаційного проходу та фінального browser QA:

- правила застосування тем і макетів винесено в `presentation-design.js`;
- чисті group/ungroup/remap та align/distribute правила винесено в `object-commands.js`;
- crop-математика stage/export узгоджена через `image-geometry.js`;
- visual text styles і SVG-геометрія фігур stage/export узгоджені через `element-rendering.js`,
  але layout, editability та DOM-контейнери лишаються відповідальністю окремих рендерерів;
- додано окремий `tests/slides-domain-behavior.html` для pure-domain, `.artslides`
  round-trip і normalization performance baseline 50 слайдів / 500 елементів;
- history більше не клонує вдруге вже відокремлений результат `serializePresentation()`;
  domain smoke перевіряє snapshot isolation, великий undo/redo, no-op deduplication,
  ліміт `MAX_HISTORY=80` і видалення найстаріших кроків;
- `renderAll()` зарезервовано для повної заміни стану (boot/open/undo/redo), а локальні
  дії використовують `renderWorkspace()` без зайвої перебудови назви файлу та палітри;
  domain smoke також має render-baseline для 50 мініатюр / 500 елементів;
- зміни об'єктів поточного слайда використовують `renderCurrentSlideThumbnail()` замість
  перебудови всього списку; повний `renderSlideList()` лишився для теми, навігації та
  структурних операцій зі слайдами, а domain smoke перевіряє збереження DOM сусідніх карток;
- autosave має покоління запитів: завершення старого запису не перезаписує актуальний status,
  а pending debounce скасовується перед новим документом, успішним відкриттям та очищенням
  чернетки; browser smoke перевіряє file-save status і відсутність воскресіння чернетки;
- готові руйнівні пресети перейменовано на «шаблони»; після застосування вони скидають
  `slide.layout` у `blank`, тоді як «макет слайда» лишається неруйнівною placeholder-операцією;
- `app.js` залишає за собою history, render, modal, status і command orchestration.

Подальше винесення робити лише за новою чіткою доменною межею. Не об'єднувати stage та
export DOM-рендерери механічно: вони мають різні правила editability, placeholder visibility
та layout.

Поточну full-snapshot history-модель залишити, доки вимірювані сценарії вкладаються у
baseline. Перехід на diff/command history потребує окремого рішення лише після відтвореного
performance або memory bottleneck.

## Найближчий Борг

Подальше дроблення `app.js` робити тільки за чіткою межею відповідальності. Для Slides найближчий борг — перевіряти реальні PPTX-файли у PowerPoint/LibreOffice/Google Slides і виправляти лише відтворені відмінності контрольованого підмноження.

(align/distribute/group, теми та layouts з placeholders — вже реалізовано, див. вище.)

## Обмеження

Не повторювати помилку надмірного дроблення. Новий модуль у `slides/js` має з'являтися лише тоді, коли він забирає самостійну відповідальність з `app.js`, додається в `sw.js` за потреби і покривається статичним аудитом або browser-smoke тестом.

Поточний висновок: Хвилю 4.5 завершено. Слайди достатньо стабілізовані для функціонального
розвитку; подальші зміни мають додавати можливості поверх зафіксованих domain/render/storage
контрактів. Наступний редактор для окремого зменшення техборгу — `paint/`.
