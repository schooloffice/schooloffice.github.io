# PPTX Import Lite — технічний пілот

Статус: пілот (D1). Пункт «Файл → Імпорт PPTX (пілот)…» відкриває лише обмежену підмножину PresentationML. Це не обіцянка відкрити будь-яку презентацію вчителя.

## Контракт

- Адаптер `slides/js/pptx-import.js`: `importPptxArrayBuffer(buffer, { fileName, limits })` повертає `{ presentation, report }` або кидає `PptxImportError` з `code` і зрозумілим `message`.
- Адаптер не змінює стан редактора й не завантажує жодних ресурсів. Результат проходить `normalizePresentation(..., { trusted: false })` — ті самі межі, що й для `.artslides.json`.
- `app.js` завантажує адаптер на вимогу (`import('./pptx-import.js')`). Далі він показує кількість слайдів і об'єктів та точний перелік втрат, а документ замінює лише після «Замінити презентацію» через `replacePresentation` з відкатом. Помилка імпорту чи «Скасувати» документ не змінюють.
- Після заміни починається нова історія. Документ позначено незбереженим, доки його не збережуть як `.artslides.json`.

## Підтримувана підмножина

| Що | Як переноситься |
| --- | --- |
| Порядок і розмір слайдів | `p:sldIdLst`; інший формат рівномірно вписується в 960×540 з полями й попередженням |
| Фон | `solidFill`; `bgRef` через `bgFillStyleLst` теми; градієнт — перший колір (попередження); зображення чи візерунок — білий (попередження) |
| Текст | абзаци, runs, `a:br`, поля як текст. Модель Слайдів має оформлення на рівні блока, тому runs зводяться до оформлення, переважного за кількістю символів (попередження про змішане форматування) |
| Список | маркований або нумерований на рівні блока; рівні вкладеності спрощуються |
| Фігури | `rect` і `ellipse` із заливкою, контуром і текстом; написи й placeholder-и — текстові блоки |
| Зображення | вбудовані PNG і JPEG (перевірка сигнатури, а не розширення), кадрування `srcRect`, прозорість `alphaModFix` |
| Перетворення | прямі `a:xfrm`: позиція, розмір, поворот. Віддзеркалення не переноситься (попередження) |

## Успадкування від макета, зразка й теми

Правила визначено заздалегідь і не розширюються мовчки.

- **Розміщення placeholder-а.** Береться з `xfrm` слайда, а якщо його немає — з макета, потім зі зразка слайдів. Відповідність шукається за `idx`, потім за точним типом, потім за групою (`title`/`ctrTitle`, `body`/`subTitle`/`obj`).
- **Стиль тексту.** Ланцюжок: run → `lstStyle` фігури → `fontRef` стилю фігури → `lstStyle` макета й зразка → `txStyles` зразка (заголовок, основний або інший текст) → `defaultTextStyle` презентації.
- **Кольори.** `schemeClr` → `clrMap` зразка з `clrMapOvr` слайда → `clrScheme` теми. `lumMod`/`lumOff` рахуються в HSL, `shade`/`tint` наближено в RGB.
- **Заливка й контур фігури.** Беруться з `spPr`, інакше з `fillRef`/`lnRef` стилю фігури.
- **Шрифти.** Гарнітури теми (`+mj-lt`, `+mn-lt`) зводяться до чотирьох родин Слайдів.
- **Декоративні об'єкти макета чи зразка.** Не переносяться; це названо у звіті.
- **Не переносяться без окремого попередження (наближення):** вертикальне вирівнювання тексту в рамці, інтервали до й після абзацу, символи й відступи маркерів, товщина контуру, конкретна гарнітура.

## Безпека й ліміти

| Межа | Значення | Помилка |
| --- | --- | --- |
| Розмір файла | 25 МБ | `too-large` |
| Записів ZIP | 2000 | `too-many-entries` |
| Сума розпакованих байтів (заявлених і фактичних) | 80 МБ | `zip-bomb` |
| Коефіцієнт стиснення запису понад 1 МБ | 100 | `zip-bomb` |
| Фактичне розпакування більше за заявлений розмір | потокова відсічка | `zip-bomb` |
| XML-частина | 4 МБ, 50 000 вузлів | `xml-too-complex` |
| DTD чи `<!ENTITY` | заборонено | `unsafe-xml` |
| Імена записів із `..`, `\`, абсолютні чи зі схемою | заборонено | `unsafe-path` |
| Шифрування, ZIP64, методи крім stored/deflate | не підтримано | `unsupported-zip` |
| Слайдів / об'єктів на слайді / зображень | 200 / 100 / 300 | `too-many-slides` / попередження |
| Зображення | 8 МБ | попередження |

- Зовнішні зв'язки (`TargetMode="External"`, `r:link`) ніколи не завантажуються.
- Цілі зв'язків, що виходять за корінь пакета, відхиляються.
- Імпорт не створює `img`, не вставляє HTML і не виконує код з файла: у модель потрапляють лише числа, дозволені кольори, текст і `data:image` PNG/JPEG.

## Перевірки

`tests/slides-pptx-import-behavior.html` (browser smoke):

- **П'ять файлів, створених Microsoft PowerPoint 16.0.** Їх генерує `tests/fixtures/compatibility/generate-pptx-fixtures.ps1`; реєстр — `registry.json`.
  - Для трьох простих перевіряються координати, розміри, кольори, тексти, списки, поворот і вписування 4:3.
  - Для двох складних перевіряється точний перелік втрат.
- **Синтетичні пакети.**
  - випадкові байти, обрізаний PPTX, ZIP без презентації, пошкоджений deflate;
  - файл понад ліміт, забагато записів, запис `../evil.xml`;
  - XML із DTD, XML із понад 50 000 вузлів, презентація без слайдів;
  - zip bomb за коефіцієнтом і з неправдивим розміром у заголовку;
  - зовнішні й пов'язані зображення, traversal у зв'язку, відсутня частина, GIF.
  - Також перевіряється, що жоден запит не пішов.
- **Збереження й відкриття** імпортованої моделі.
- **Редактор.**
  - відмова зберігає документ і пояснює причину;
  - підтвердження показує точні втрати, «Скасувати» нічого не змінює;
  - «Замінити презентацію» застосовує модель, Undo не повертає старий документ.

## Точність

Рендер PowerPoint (`Slide.Export`) порівняно зі знімком імпортованого слайда 960×540 (`createSlideSnapshot`) у headless Chrome.

- **Прості зображення.** Позиції, розміри й поворот збігаються; підпис відрізняється лише гарнітурою.
- **Титульний слайд.**
  - Розміри й позиції рамок збігаються.
  - Заголовок стоїть угорі рамки, а в PowerPoint — унизу (вертикальне вирівнювання `anchor="b"` не переноситься).
- **Фігури.**
  - Розміри, позиції, заливки, колір тексту й кольори контурів збігаються.
  - Контур у Слайдах помітно товщий, кути прямокутника заокруглені, контур кола обрізано рамкою. Це обмеження рендера й моделі фігур, а не читання PPTX.
- **Формат 4:3.** Вписування з полями й поворот правильні; інтервали між пунктами списку тісніші, ніж у PowerPoint.
- **Складні файли.** Імпортовано лише названі у звіті об'єкти; все, що не перенесено, перелічено.

## Тривалість, пам'ять, bundle, ліцензія

- **Час у вбудованому Chromium (реальний час, локальний сервер).** П'ять файлів корпусу (37–45 КБ) імпортуються за 6–29 мс.
- **Стрес-сценарій: 25 слайдів × напис і PNG 0,8 МБ (архів 19,1 МБ).**
  - імпорт займає 261 мс;
  - heap зростає на ≈27 МБ;
  - модель у JSON важить 25,5 МБ (зображення base64).
- **Не виміряно:**
  - застосування до редактора (мініатюри, історія, чернетка в IndexedDB);
  - роботу на слабких шкільних пристроях;
  - пікову пам'ять (`performance.memory` у Chrome квантований).
- **Bundle.** Модуль важить 47,7 КБ без мініфікації. Він завантажується лише на вимогу й кешується Service Worker для офлайн-роботи.
- **Залежності й ліцензія.** Нових залежностей немає: використовуються нативні `DecompressionStream` (Chrome 80+, Firefox 113+, Safari 16.4+) і `DOMParser`. Код власний, під кореневою MIT-ліцензією проєкту.

## Рішення за підсумками пілота

Вузька production-підтримка можлива для простих навчальних презентацій: текст і placeholder-и, прямокутники й овали, вбудовані PNG/JPEG. Позначку «пілот» варто зняти лише після кількох кроків:

1. Перевірити файли, створені вчителями (а не лише згенеровані), і хоча б один незалежний експорт з іншої програми (Google Slides, LibreOffice Impress).
2. Перенести вертикальне вирівнювання тексту й інтервали абзаців або явно назвати їх у звіті.
3. Додати в модель фігур товщину контуру: без неї тонкі контури PowerPoint виглядають грубо.
4. Розширювати підмножину за частотою втрат у реальних файлах. Першими кандидатами є об'єкти, які модель Слайдів уже вміє зберігати: таблиці, нотатки, трикутник, лінія, стрілка, заокруглений прямокутник. Далі — розгортання груп.
