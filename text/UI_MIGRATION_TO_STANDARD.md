# UI_MIGRATION_TO_STANDARD.md — ПЛЮС Текст

## Поточний стан

Базовий shell, command adapter, file picker і modal/dropdown контракти підключені.
Локальна структура вже вирівняна до `text/js/runtime.js -> text/js/app.js` поверх шарів `text/core/`, `text/ui/` і `text/formats/`.

UI-шар стабільний, але **головний борг редактора не в UI, а в архітектурі ядра**. Не зводити план робіт лише до полірування інтерфейсу.

## Архітектурний борг (пріоритет)

Корінь проблем спільний: DOM водночас є документом, сторінковою версткою і станом історії. Повний перелік відомих дефектів і їхні джерела зафіксовано в `../PROJECT_DIRECTION.md` (розділ 4, «Поточні відомі дефекти Text»). Стисло:

- окремі `contenteditable` на сторінку ламають наскрізну навігацію й виділення між сторінками;
- історія зберігає сторінковий DOM, а не логічний документ;
- пагінація не ділить таблиці;
- таблиці мають лише базову вставку (без `Tab`-навігації, рядків/колонок, ширини, merge/split);
- DOCX не є повним round-trip;
- немає поведінкових тестів Text.

Порядок робіт і пілоти (Custom single-flow / ProseMirror / Lexical) описані в узгодженому плані; цей файл лише фіксує, що UI-полірування є вторинним щодо цих дефектів.

## Найближчий UI-борг (вторинний)

- Перевірити, чи toolbar Save і Ctrl+S мають однаково очікувану поведінку для користувача.
- Вирівняти confirm/info/prompt тексти після ручного браузерного QA.
- Переглянути контекстні дії для таблиць і зображень, щоб не тримати зайве в постійному toolbar.
